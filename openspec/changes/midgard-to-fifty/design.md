## Context

See proposal.md for why. What the code and data hold today:

- **Collision.** `world/collision.go` bins hull triangles and trunk cylinders per zone (outdoor and interior), and the outdoor `Mover` also samples the heightmap. It answers `Slide` and `FloorBelow`. There is no segment query yet.
- **Combat between creatures.** NPCs fight through the `combatant` interface and a hate list (`combatant.go`), and guards already fight creatures. A pet can be an NPC with an owner, built on the same machinery.
- **Effects.** `effects.go` handles stat, armour factor, resist, speed and regeneration buffs, damage over time, slows, mesmerize and stun, each with a timer. It has no untimed effects and no debuffs.
- **The world store's spell table.** It has `life_drain` (the summon template id in the data), `sub_spell`, `radius`, `pulse` and `power`. It lacks `Concentration`, `ResurrectHealth`, `ResurrectMana` and `IsFocus`.
- **The world store's `npc_template` table.** It holds model, size, level, speed, aggro, defences and melee type. It lacks stats, body type, spells, styles and left-hand chance.
- **Midgard data quests.** All 81 of the community data's Midgard `dataquest` rows are "XP Item" collection turn-ins (checked 2026-11-19). The data has no task table content: tasks in the community server are generated by code.
- **Items for loot.** The item data holds 160 to 520 droppable Midgard or neutral armour pieces per five-level band through 46-50, and 63 to 268 weapons. Generic loot (`randomDrop`, level − 2 to level) already reaches 50. The merchant lists stop at 30.
- **Class data.** The data's class table agrees with the proposal's spec list for the four new classes. Their trainers stand in the world, 8 placements each.

## Goals / Non-Goals

**Goals:**
- Four parts (A group essentials, B gear, C pets and classes, D tasks). Each one is shippable to the live server on its own, in that order.
- Every new mechanic is a rule-book entry with sources and status, before its code, as `thane-and-skald` did.

**Non-Goals:**
- A general NPC scripting system.
- Line of sight for melee (melee already needs reach).
- Creature area spells.
- Player-versus-player stealth balance.
- Pets in the offline viewer.

## Decisions

1. **Sources first, per part.** Each part opens with a findings section in `findings.md`. It reads DOLSharp and OpenDAoC-Core (to understand the mechanic only, nothing copied) and searches for a published 1.65 account: disorder.dk, the Camelot Herald, Allakhazam, Grab Bag. It covers that part's numbers:
   - concentration pool and range, resurrection experience and sickness;
   - merchant gear by town;
   - pet level, charm break, archery damage, stealth detection and speed, poison chance and charges, left-hand chance;
   - task limits and reward.

   Every "set by the findings" status in the specs is settled there, and any new source is added to CLAUDE.md and the README. *Alternative:* take the community servers' numbers wholesale. Rejected, because the rule book asks for our words and a status.
2. **Line of sight is a segment query on the existing collision bins.** `Collision.Visible(a, b [3]float64)` walks the bins the segment crosses (a DDA walk over the ground grid). It tests:
   - triangles that block (the `wallNZ` filter is not applied, since a roof also blocks sight);
   - cylinders, by their z range;
   - the heightmap, sampled every half bin along the segment.

   Eye height is a constant. Results are not cached: a cast checks twice and creature casts are rare. *Alternative:* a separate coarse visibility grid. Rejected, because the existing bins are already in memory and exact enough. A zone without collision data passes every check, so the offline and test zones are unaffected.
3. **Untimed effects carry their source.** An effect gains `caster` and `conc` fields. A concentration effect has no expiry. Instead, a once-a-second sweep in the zone tick checks range and grace time, and ends the effect, returning its cost to the caster's `concUsed`. Caster death, zoning and cancel end it the same way. Songs (`songs.go`) stay as they are: they already keep effects alive by refreshing them.
4. **Debuffs are negative buffs.** Stat and resist debuffs use the same aggregation as buffs, with the strongest debuff per kind subtracted. Creature stats go through the same `rules.Combatant` fields, so a debuff on a creature changes its melee through the existing formulas. Disease, nearsight, confusion and amnesia are new effect kinds with small, separate handlers.
5. **A pet is an NPC with an owner and a brain mode.** `NPC.owner *Player`, a `petMode` (follow, stay, attack) and a stance. It reuses movement, swing, casting and the hate list. Its target choice is replaced by its owner's orders and stance.
   - Experience and loot go to the owner through the existing kill path, by mapping the killer to the owner.
   - A creature's hate for a pet also adds the owner.
   - Bonedancer minions are pets whose `leader` is the commander, and they take the commander's target.
   - Charm takes an existing NPC: it clears its hate, sets its owner, and keeps its spawn. On release or break, the NPC goes back to its spawn rules, made hostile to the former owner on a break.

   *Alternative:* a separate pet entity type. Rejected, because it would duplicate the combat code that guards already share.
6. **Pet models are converted like any creature.** The set of models the summon templates name is listed by a `cmd/parity`-style helper, so the first-run recipe can convert them. A missing model draws the client's fallback, as for creatures today.
7. **Archery is a ranged swing, not a spell.** It is a draw state on the player, like `casting`, shown on the cast bar.
   - On release, the arrow resolves through the melee pipeline with parry turned off and the ranged damage formula.
   - It uses one arrow from the quiver slots, and line of sight is checked at release.
   - Critical Shot, Rapid Fire and Penetrating Arrow change the draw time and damage, or set a flag that bladeturn checks.

   The quiver slots are added to inventory additively. The protocol gains `shoot` (client) and a draw event.
8. **Stealth is a visibility filter in the zone's broadcast.** `world-sync` already chooses what each client receives. A hidden player is left out of another client's updates unless that viewer is within detection range. Creature aggro checks use the same test. Stealth speed goes through the movement speed factor, with a shared Go/JS vector, as the speed song did.
9. **Poisons are a weapon proc slot with charges.** A worn weapon gains `poison` (spell id and charges), stored with the item row. The existing weapon-proc path fires it.
10. **Left hand follows the dual-wield rule from the findings.** It is applied in the player swing after the main hand, with its own `rules` function and table test. Savage hand-to-hand uses the same function, and its weapon kind is enabled when the rule lands.
11. **Merchant stock for 31–50 is a project table.** `internal/importer/addedstock.go` lists, for each band, the merchant list it extends and the item ids chosen. Items are chosen by a rule: non-unique, no stat bonuses, quality at the findings' merchant quality, Midgard or neutral. `dbimport` writes the stock into `merchant_stock` with an `added` flag. The census reads the flag. *Alternative:* edit the data's merchant lists. Rejected, because the data must stay as imported.
12. **Tasks are generated by code, persisted per character.** Task givers are chosen by a rule: named townsfolk with no other role in towns, set by the findings. A kill target is picked from the zone's placements by con band, and a delivery target from the region's NPCs. `players.db` gains a `task` table (character, kind, target, giver, progress, expiry). The protocol gains `task` (the state) and an `ask-task`/`abandon-task` request.
13. **Data quests are marked not classic in `notclassic.go`**, with the same mechanism and census column as teleporters.
14. **Protocol and windows.** All new messages are additive and documented, with a protocol test each: `pet`, `pet-cmd`, `conc`, `conc-cancel`, `rez-offer`, `rez-answer`, `shoot`, `stealth`, `task`. Each new window (pet, concentration, resurrection prompt, task) has a stock-layout version when one exists in the converted UI and a plain panel otherwise, and is checked in the browser both ways.

## Risks / Trade-offs

- [The change is large] → It ships in four parts. Each part ends with tests, the census, the README and a live switch. Parts C and D can be split into their own changes at apply time without changing the specs.
- [Line of sight on hulls built for walking may be too coarse or too fine] → Check it in the browser in Jordheim, a dungeon and a forest. The eye height and the triangle filter are constants that can be tuned.
- [Untimed effects could leak if an end path is missed] → A test kills, zones and disconnects the caster and asserts the target's effects and the caster's `concUsed`.
- [Pets roughly double NPC work for an owner] → Fine at friends scale.
- [Stealth filtering could desync prediction] → Hidden players are simply absent, as they are when out of range, so the existing entity enter and leave path handles it.
- [Sources may be thin for archery, stealth and task numbers] → Those rules are provisional, and the status shows it.
- [Pet models may be missing from the conversion] → The fallback model applies, and the README recipe lists the models.

## Migration Plan

For each part:

1. Back up `players.db`.
2. Re-run `dbimport` if the part changes the importer (parts A, B and C do). The staged store is swapped in at start.
3. Rebuild and restart `gameserver`.
4. Part C also converts the pet models.
5. Part D adds the `task` table to `players.db` on start, additively.

Existing characters load unchanged. A store imported before a part loads with that part's features refused as unsupported. To roll back, restore the backup and the previous `world.db` (kept as `world.db.prev`).
