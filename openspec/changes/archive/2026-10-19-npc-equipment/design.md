## Context

Observed today: `spawn` (importer `world.go`) keeps name, guild, model, stats and flags, but no equipment. `npcequipment.sql` holds about 52,000 rows with columns `TemplateID, Slot, Model, Color, Effect, Extension, Emblem`; `mob` and `npctemplate` both have `EquipmentTemplateID`. Slots used in the data: 10 right hand, 11 left hand, 12 two-hand, 13 ranged, 21 helm, 22 gloves, 23 boots, 25 torso, 26 cloak, 27 legs, 28 arms (slot names from documented game mechanics; slot 24 jewellery and 14 to 20 do not occur). Each creature is converted separately to `web/data/char/m<N>` and chosen by `'m' + e.model`; players use an outfit assembled by `charconv` from named shapes per slot. README says the install's item-to-armour mapping has not been found, and CLAUDE.md says icon numbers in the imported data do not match the install, so item model numbers are not trusted yet.

## Goals / Non-Goals

**Goals:** import and link the equipment; send it additively; draw what can be resolved; fail soft; record the faces answer.

**Non-Goals:** weapon effects, shield emblems, guessing an offset to force numbers to match (forbidden by CLAUDE.md).

## Decisions

1. **Store equipment as rows keyed by template id**, with `equip` on `spawn` as the template id. Resolve in `Catalog` once per template and cache; spawns share templates heavily. Denormalising into each spawn was rejected for size.
2. **Wire format:** entity field `eq`, a list of `[slot, model, color, ext]` arrays, omitted when empty. Compact, additive, covered by a protocol test. Clients cache by NPC id since gear does not change in play.
3. **Resolve model numbers first, as a spike.** Before any drawing, test whether `npcequipment.Model` lines up with shapes in the install (compare a few well-known NPCs such as guards against their expected look). The outcome decides scope: if numbers resolve, build a lookup file generated by a converter into `web/data/` (never committed); if they do not, fall back to drawing by slot and armour tier from the item's weapon line or kind, the approach the stock UI already uses, and say so.
4. **Client composition:** reuse the player outfit path in `character.js` (shape per slot, texture per slot, items on bones) for NPCs whose base model has those slots; creatures whose model has no armour slots ignore body pieces.
5. **Faces and heads:** read the NIF shape names for a humanoid NPC model and check whether heads are separate shapes chosen by helm model or `Extension`. Record the result here; draw only if it is a simple selection.

## Risks / Trade-offs

- Numbers may not match the install, giving wrong or no gear. Mitigation: the spike comes first and drawing is optional per piece.
- Per-creature conversion could balloon disk and load time if every gear variant is baked. Mitigation: share slot meshes across NPCs and load lazily on first sighting.
- Snapshot size grows with gear. Mitigation: send once per entity appearance rather than every tick if measurements show a cost.

## Open Questions

- Do `Model` values refer to the same numbering as `itemtemplate.Model`, and does either match the install?
- Is `Extension` an armour tier, a texture variant or a head selector?
- How do colour values map to tints (`color.dat` in the install is a candidate)?

## Spike findings

Sampled NPCs (guards, a guardsman set, a ranger, wizards, a werewolf warder) against `gamedata.mpk` tables extracted with `mpakls`:

- **Armour is set-numbered.** A full set uses one model number per slot (a guardsman wears legs 47, arms 48, hands 49, feet 50, torso 662, helm 93, cloak 91). Only some numbers appear in `pskins.csv` (662 is `h_scl1_body1f.tga`); 47 to 50, 93, 91 and the Master Guardian set (428 to 432) do not. The database's numbers therefore do not index the install's armour skins directly.
- **Held items partly resolve.** `items.csv` ids give a NIF per number, and some agree with the NPC (311 Hib 2H mace on a werewolf warder, 315 Hib 2H Firbolg mace, 444 Albion mage staff on a reanimated guardian). Others plainly do not (79 is a bow, 473 a shield, both in the wrong slot; 3, 4, 19 and 22 are absent). The numbers are usable per piece only when the item kind agrees with the slot.
- **Colour resolves.** `Color` is a `tints.csv` id (189 rows: 17 Iron, 43 Black Cloth, 70 Green 3, ...), an RGB per row.
- **Faces and heads are not equipment-driven.** `monsters.csv` gives every humanoid model its own Head skin plus Face and Hair columns (Firbolg Male 1 has Head 1021, Face 292, Hair 9), so the head belongs to the base model. The equipment `Extension` was 0 in every sampled row. The helm slot only adds a helm piece (`items.csv` has a "Helm Hair" column). Result: the head is chosen by the creature's `monsters.csv` row, not by equipment. Why NPCs show no face today is not yet known (the per-creature converter may not apply the Head skin); that is a converter question for task 4.5, separate from gear.

Consequence for scope: held items can be drawn where `items.csv` and the slot agree; body armour cannot be resolved by number and falls back to the slot's armour tier chosen by the NPC's realm, as the player outfits are. Tasks 4.1 and 4.3 are adjusted accordingly once this is agreed.
